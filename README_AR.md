# Ctrl+Tea Lecture Studio

تطبيق محلي لتأليف المحاضرات الجامعية العربية ومراجعتها وتصدير Word قابل للتعديل وPDF مرجعي للطباعة. لا يحتاج حسابًا أو خدمة سحابية. يعمل التأليف عبر حزمة تُفتح في OpenCode أو مؤلف خارجي، ثم تُستورد النتائج إلى المحرر.

## Windows

لنسخة Windows x64: افتح `Install-Windows.cmd` مرة واحدة، ثم `Start-Windows.cmd`. التشخيص عبر `Check-Windows.cmd`. اقرأ [دليل ويندوز](README_WINDOWS_AR.md) وحدود الاختبار؛ هذه حزمة تشغيل وليست EXE مستقلًا. لا تحتاج Nix أو Node للتشغيل.

## حزمة التنزيل المصححة

أُعيد تحزيم المشروع بعد اكتشاف أن الأرشيف السابق انقطع قبل كتابة فهرس ZIP النهائي وبعض ملفات التشغيل. محرك العرض والبيانات المرجعية السليمة محفوظة كما هي، والواجهة أعيد بناؤها وطابقت ملفات JavaScript وCSS للنسخة الأخيرة. لا تحتاج إعادة التأليف.

الأرشيف الجديد يُكتب أولًا باسم مؤقت، ويُغلق ويُفحص قبل إعطائه اسمه النهائي. يحوي ملفات التشغيل والواجهة المبنية والخطوط والأمثلة؛ لا يحوي بياناتك الشخصية أو `node_modules`. احتفظ بمجلد `data` الحالي عند تحديث البرنامج.

للتأكد من تنزيل ZIP كاملًا: `unzip -t CtrlTea_Lecture_Studio_V1.zip`. توجد نسخة `tar.gz` بديلة على Linux. يمكن إنشاء ZIP مماثل بواسطة `python scripts/package_release.py /path/to/release.zip`.

## إصلاح OMML واتجاه العربية والإنكليزية

المعادلات باقية أصلية قابلة للتعديل. ضُبط Latin Modern Math على 14pt في DOCX وفي إعداد Math المؤقت لـPDF، مع عزل المعادلات المضمنة باتجاه LTR ومنع ارتفاع السطر الثابت من قصها. أضيف رفض للتصدير عند اكتشاف تداخل كبير بين الرياضيات والمتن. نجح 96 اختبارًا و12 حالة تصدير من الداشبورد؛ المراجعة المرئية بـLibreOffice، وليس Microsoft Word. التفاصيل والعينات والحدود في [تقرير إصلاح المعادلات](docs/OMML_REVIEW_AR.md). حدّث ملفات البرنامج مع الاحتفاظ بـ`data` ثم أعد التصدير فقط.

## تحديث Ctrl+Tea Study Notes

المتن والعناوين بالعربية والإنكليزية الآن بخط **Cairo**، مع نقطتين وخط أسفل عناوين المحتوى، وفاصل أسود رفيع بين الفقرات المتجاورة. الصناديق بخلفيات أهدأ وحدود كاملة أخف وحشو مريح؛ تبقى الملاحظات القصيرة متماسكة. الغلاف والفوتر محفوظان. الخطوط وترخيصها داخل `assets/fonts`؛ ثبّتها على جهاز Word إذا أردت الخط نفسه عند فتح DOCX خارجيًا.

أُعيد تصميم الصفحات الداخلية بصناديق أكاديمية للتعاريف والقوانين والأمثلة والملاحظات، مع إبقاء الشرح خارجها، والسؤال والمعطيات داخل إطار والحل خارجه والنتيجة في شريط صغير. الغلاف والفوتر والثيمات الثلاثة محفوظة. يكفي إعادة التصدير لتطبيقه على محاضرة قائمة؛ لا يُشغَّل المؤلف ولا يتغير المحتوى العلمي.

أصبح نجاح PDF مشروطًا بفحص ظهور معادلاته ورموزها والحبر داخل مناطقها، وليس وجود OMML في Word فقط. يتطلب LibreOffice مكوّن **Math** بالإضافة إلى Writer؛ تثبيت Writer وحده قد يخفي المعادلات رغم نجاح التحويل. بيئة Nix المرفقة تختار LibreOffice الكامل. لا تحذف مجلد `data` عند تحديث ملفات البرنامج.

العينات الحالية في `examples/study-exports`: التحكم والإحصاء بالثيمات الثلاثة، وثلاث عينات خطوط من ست صفحات لكل منها. التفاصيل في [تقرير المراجعة](docs/STUDY_NOTES_REVIEW_AR.md)، والمقارنة الفعلية في `docs/Study_Notes_Visual_Review.pdf`. التقارير الأقدم محفوظة كتاريخ للمراحل السابقة.

## التشغيل على NixOS

من مجلد المشروع:

```bash
nix develop
python scripts/start.py
```

افتح http://127.0.0.1:8765. الواجهة المبنية موجودة في الحزمة؛ لا تحتاج إعادة بنائها للتشغيل الأول. أول تحميل لحزم Nix يحتاج الإنترنت. ملف flake.nix يثبّت مراجعة nixpkgs محددة، ويجهز Python وLibreOffice وPandoc وTesseract العربي والإنكليزي والخطوط وChromium للاختبارات.

**بيئة Nix نفسها لم تكن متاحة أثناء التطوير؛ لم يُختبر أمر nix develop هنا.** اختُبر التطبيق فعليًا على Linux وPython 3.12 مع الأدوات المذكورة، وتوجد أدناه أوامر التحقق لإعادة الاختبار على جهازك.

لإعادة بناء الواجهة بعد تعديلها:

```bash
cd frontend
npm ci
npm run build
cd ..
python scripts/start.py
```

لمنفذ آخر: `python scripts/start.py --port 8766`. يشغّل البرنامج خادمًا واحدًا على localhost؛ لا تعرضه للشبكة العامة. أثناء التطوير، شغّل الخادم ثم `npm run dev` داخل frontend.

## التشغيل على Linux دون Nix

ثبّت Python 3.11 أو أحدث وNode.js 22 أو أحدث وPandoc وLibreOffice وTesseract مع ara وeng وFontconfig وLatin Modern Math ومكتبات Cairo. ثم:

```bash
bash scripts/setup.sh
.venv/bin/python scripts/start.py
```

يثبت setup الخطوط المرفقة في مساحة المستخدم. على Nix تستخدم إعدادات Fontconfig المعرّفة في flake الخطوط المرفقة مباشرة. لا يستدعي التطبيق Gemini ولا أي نموذج تلقائيًا.

## أول محاضرة

1. أنشئ مقررًا، ثم محاضرة. أضف اسم الدكتور الفعلي في الإعدادات.
2. ارفع المصدر الأساسي، ثم الكتاب أو المحاضرات الداعمة. الرقم الأصغر يعني أولوية أعلى. اختر المصدر الأساسي صراحة.
3. افحص النص المستخرج؛ يختلف OCR واستخراج PDF عن المطابقة البصرية. صحّح النص بجانب الأصل، واستبعد الكلام غير التعليمي من النسخة المصححة. يبقى الأصل محفوظًا.
4. للتفريغ الخارجي ارفع TXT أو Markdown واربطه بملف PDF الأصلي. يمكنك إضافة «ربط صفحة تفريغ» لتوزيع النص المصحح على أرقام صفحات الأصل. الفاصل form feed بين الصفحات مدعوم أيضًا. الربط يتيح المطابقة ولا يشهد على صحة التفريغ.
5. جهّز أقسام المحاضرة في المحرر إن كانت طويلة. يمكنك أيضًا البدء دون أقسام ليقترح المؤلف تقسيمها.
6. من التأليف نزّل الحزمة. افتحها في OpenCode أو مؤلف تختاره واطلب اتباع instructions.txt وmanifest.json وschema.json. يوجد result-example.json لبنية النتيجة، وليس محتوى علميًا جاهزًا.
7. استورد JSON، وراجع المعاينة والملاحظات. يمكن استيراد قسم أو مجموعة أقسام في كل مرة. علّم الأقسام المكتملة حتى تستبعدها حزمة الاستكمال التالية. الاستيراد يحذر عند استبدال محتوى سبق تعديله.
8. عدّل الكتل، المعادلات، الجداول، المراجع ومواصفات الرسومات. ولّد كل رسم للمراجعة. فحص Word ينشئ OMML فعلية ولا يختبر Microsoft Word.
9. جهّز Word وPDF. راجع جميع صفحات PDF، والرسومات، ونصوص الأسئلة، والوحدات. راجع الفهرس وروابطه. يمكنك تنزيل مسودة دون انتظار معالجة كل الملاحظات العلمية.
10. من المقررات صدّر المشروع كاملًا. استعادته تنشئ نسخة مستقلة وتحافظ على المصادر والتصحيحات وسجل المحتوى ومهام التأليف. تبقى نتائج الحزم الخارجية القديمة قابلة للاستيراد في المشروع المستعاد.

## الحفظ والاستعادة

- تغييرات محتوى المحاضرة تحفظ بعد مهلة قصيرة. أزرار التراجع والإعادة تعمل داخل الجلسة، وسجل النسخ يسمح باستعادة حالة أقدم بعد الإغلاق.
- تصحيح المصدر يحفظ تلقائيًا؛ تتوفر أيضًا زر حفظ. عند مغادرة الصفحة بسرعة تبقى النسخة المحلية غير المحفوظة ليستعاد العمل عند العودة.
- النص المصحح لا يستبدله OCR. يعاد استكمال الاستخراج من الصفحات غير المنجزة.
- المهام وحالتها في SQLite؛ المهام التي انقطع تنفيذها تُعاد إلى قائمة التنفيذ عند تشغيل البرنامج. عمليات التصدير تعاد من البداية بأمان، بينما الاستخراج يستأنف على مستوى الصفحة.
- لا تفتح التطبيق نفسه بخادمين على مجلد البيانات نفسه. نافذتان في خادم واحد تستخدمان فحص الإصدار لمنع الكتابة فوق تعديل أحدث.
- البيانات في data/ أو المجلد المحدد بمتغير CTRLTEA_DATA_DIR. انقل المشروع عبر زر التصدير بدل نسخ SQLite أثناء التشغيل.

## المعادلات والرسومات

المعادلات تحفظ بصيغة LaTeX وتتحول باستخدام Pandoc إلى OMML أصلية. الكسور المتداخلة والمشتقات والأسس والمؤشرات والتكاملات والمصفوفات والجذور والصيغ الرياضية الشائعة مغطاة بالاختبارات. أمر LaTeX غير مدعوم يفشل برسالة؛ لا يحول إلى صورة ولا يسقط بصمت. المعاينة في المحرر تستخدم KaTeX؛ الحكم النهائي على التخطيط هو PDF المحول من DOCX.

للرياضيات داخل النص: `\(x_i^2\)` أو `$x_i^2$`. لا تضع علامة الدولار حول المعادلة في كتلة المعادلات.

الرسومات المتاحة: الخطوة، والمائلة، والنبضة الرمزية، والمنحنيات، والمبعثر، والأعمدة، والمدرج، ومخططات الكتل، والدارات الأساسية (أسلاك، مقاومات، مكثفات، ملفات، مصادر جهد)، والقص من PDF. الدارات لا تنفذ محاكاة ولا تستنتج التوصيلات. تدخل التوصيلات صراحة من المصدر.

الدوال تستخدم لغة عددية محددة: x أو t وpi وe وsin/cos/tan/exp/sqrt/log/abs/step والحسابات العادية. لا يُنفذ كود Python من المؤلف. يوجد SVG أصلي داخل Word مع PNG احتياطي لتوافق القراء. تبقى الرسومات قابلة لإعادة التوليد من مواصفاتها في المشروع؛ لا يُدّعى أنها كائنات رسم Word قابلة للتحرير جزءًا جزءًا.

## الهوية ولون المحاضرة

اختر «لون المحاضرة — Lecture Theme» عند الإنشاء، أو افتح إعدادات المحاضرة لتغييره لاحقًا. تعرض العينات القرفة Cinnamon والعسل Honey والزيتوني Olive، مع شكل الصندوق والفوتر. يُحفظ الاختيار مباشرة، ويظل محفوظًا بعد إغلاق البرنامج وفي المشروع المنقول. للمحاضرات القديمة يُضاف اللون الافتراضي القرفة بترحيل SQLite تلقائي دون تغيير نص المحاضرة أو سجلها.

ثيم واحد ثابت لكل المحاضرة، دون تناوب بين الصفحات أو الأقسام. يتبع الفوتر العريض والعناوين والجداول والرسومات المنشأة هذا الاختيار. احتُفظ بقياسات الفوتر وشكل شعار الفريق المستخرج من control-original.pdf، مع خلفية Dark ورقم صفحة أصلي كبير، ونصف Medium للشعار. الغلاف يحتفظ بالشعار والشخصية وشريط الألوان الأصليين، مستقلًا عن لون المحاضرة.

التعاريف والقوانين والأمثلة بعناوين منفصلة واضحة داخل إطارات كاملة. الملاحظات والنتائج القصيرة بعناوين مدمجة وخلفيات أخف. ألوان الصناديق مشتقة من Light مع الورق الأبيض، وعناوينها من Dark. نص المسألة ومعطياتها داخل إطار، والحل خارجه. رأس الجدول Dark ونصه أبيض، والصفوف فاتحة متناوبة. إذا احتوى رأس الجدول معادلة، تظهر المعادلة على مساحة Light داخل الرأس الداكن لأن LibreOffice يستورد OMML بالأسود. المعادلة تبقى أصلية دون تغيير رموزها. لا يُفرض فاصل صفحة لتغيير اللون؛ اختُبر قسمان في صفحة واحدة. الرسومات تستخدم اللون أثناء التصيير، والقصاصات الأصلية تحتفظ بألوان المصدر، مع أنماط خطوط وعلامات لتمييز المنحنيات في الطباعة الرمادية.

تغيير اللون لا يعيد التأليف، ولا يكتب JSON العلمي، ولا يغيّر معادلات LaTeX أو الجداول أو المصادر. تتحدث معاينة الثيم والقراءة السريعة؛ في قسم المعاينة والتصدير اضغط «تجهيز Word وPDF» لتحديث المستند. النسخ القديمة تبقى متاحة، وتظهر رسالة إذا اختلف لونها عن الإعداد الحالي.

أسلوب المحتوى الداخلي مستوحى من mousse-notes ويستخدم Cairo للنص العربي والإنكليزي ولعناوين المحتوى، بينما تبقى خطوط الغلاف والفوتر المعتمدة كما كانت. ضُبطت ascii وhAnsi وcs في المقاطع المباشرة؛ الأحجام الافتراضية 13.5 نقطة للعربية و13 للإنكليزية، مع تباعد أسطر أدنى 25 نقطة. الخطوط الثابتة وأذونها في assets/fonts، وتستخدم القراءة السريعة Cairo أيضًا. ثبّت الخطوط المرفقة عند فتح DOCX على جهاز آخر.

معادلات OMML تحتفظ بـLatin Modern Math وبالرموز الأصلية. LibreOffice يستخدم محرك Math مع إعداد التطبيق Latin Modern Math في PDF؛ لم يُغيّر محوّل المعادلات في تحديث التصميم. ترتيب أعمدة الجدول منطقي من اليمين إلى اليسار دون عكس يدوي للقيم. رأس الجدول يتكرر عند امتداده إلى صفحات متعددة. الفهرس داخل الغلاف ينشأ من الأقسام الفعلية بروابط داخلية؛ لا يعتمد على أرقام صفحات متوقعة. إذا طال الفهرس يتابع على صفحات إضافية دون الاصطدام بالشخصية؛ يوجد قسم Word للغلاف وآخر للمحتوى، ولا تُنشأ أقسام Word لكل قسم علمي.

## أمثلة من المصادر المرفقة

- examples/control.document.json: إعداد أكاديمي مرجعي لمحاضرة التحكم المرفقة، مع مراجع الصفحات وقضايا علمية للمراجعة.
- examples/statistics.document.json: **مقتطف اختبار** من الفئات والتكرارات والمساحات في المحاضرة؛ ليس المحاضرة الكاملة.
- examples/references/: ملفاتك الأصلية للمطابقة.
- examples/exports/: المخرجات التي جرى توليدها واختبارها فعليًا إن كانت مرفقة بالحزمة النهائية.
- examples/projects/: مشاريع قابلة للاستعادة عبر الداشبورد إن كانت مرفقة.

لإعادة تصدير المشاريع المحفوظة دون إعادة تأليف أو OCR:

```bash
PYTHONPATH=backend python scripts/render_examples.py
# العينتان بالألوان الثلاثة، دون تشغيل المؤلف:
python scripts/render_examples.py --all-themes --output examples/exports/themes
python scripts/verify_theme_exports.py --input examples/exports/themes
```

يعيد السكربت التصدير إلى examples/exports، ويقارن النصوص وبنية جميع المعادلات بالمحتوى المحفوظ. نتائج المقارنة البصرية موثقة في docs/DESIGN_REVIEW_AR.md وdocs/Design_Review.pdf. نسخة مصادر mousse-notes وأمثلتها في docs/references للتوثيق؛ لا يحتاج التشغيل أو التصدير إلى Typst.

لإدخال المثالين في تطبيق جديد:

```bash
python scripts/seed_examples.py
```

هذا الأمر ينشئ مقررين جديدين ولا يستبدل عملك. ملفات JSON المرجعية تستخدم معرفات مصادر رمزية؛ السكربت أو مشاريع الاستعادة المرفقة يتكفل بربطها بالأصول.

## التحقق

```bash
python -m pytest -q
python scripts/e2e.py
```

اختبار المتصفح يشغل خادمًا وقاعدة مؤقتين، ويختبر إنشاء مقرر ومحاضرة ورفع PDF وتفريغ وتصحيحه وربطه بالأصل، وتأليفًا خارجيًا على دفعتين واستكماله، وتحرير جدول ومعادلة ومواصفات رسم، وإعادة التحميل، والتصدير عبر الداشبورد، وتنزيل DOCX وPDF، وتصدير مشروع واستعادته. ثم يختبر المحاضرتين بالألوان الثلاثة عبر الواجهة، ويوقف الخادم ويعيد تشغيله للتحقق من بقاء اللون. يقارن JSON العلمي الخام وسجل النسخ والمصادر والتأليف قبل التبديل وبعده. لا يستدعي نموذج LLM؛ يستخدم نتائج تأليف مرجعية صريحة لاختبار بروتوكول المؤلف.

يحتاج Chromium؛ flake يضبط CHROMIUM_EXECUTABLE_PATH. دون Nix يمكنك ضبطه إلى متصفح مثبت، أو تشغيل `python -m playwright install chromium`. صور التحقق وتقاريره تكتب في output/e2e. اختبارات الوحدات والتكامل مستقلة عن المتصفح.

**لم يتوفر Microsoft Word أثناء التطوير.** التحقق البنيوي لمعادلات OMML والتحويل والمراجعة البصرية تم باستخدام LibreOffice. PDF هو المرجع الرسمي للتنسيق؛ تعديل Word خارجيًا قد يغير تقسيم الصفحات، ولا يعود تلقائيًا إلى المشروع.

مراجع الصفحات وفحوص وجود المعادلات لا تثبت صحة جميع المعلومات العلمية أو تغطيتها. تبقى مراجعة المحتوى والأسئلة والبيانات والرسومات مسؤولية المحرر. الملاحظات تُعرض دون نظام موافقات يمنع تحرير المحاضرة أو استخراج مسودة.


## تحديث الطباعة والتأليف الأكاديمي

يستخدم جسم المحاضرة محاذاة عربية طبيعية إلى اليمين، وNoto Naskh Arabic مع Source Serif 4 ومعادلات Latin Modern Math. الغلاف والفوتر والثيمات ثابتة كما كانت. تدعم الكتل قائمة أصلية قابلة للتحرير، وتُرفق حزمة التأليف بمدقق كامل يشغّل قبل تسليم JSON. لا تعاد كتابة المحاضرات الحالية عند التصدير.

تفاصيل المقارنة والمراجعة والحدود في [المراجعة الأكاديمية](docs/ACADEMIC_REVIEW_AR.md). المحاضرة الحالية المعاد تنسيقها وعينة النمط الحديث في `examples/academic-exports`، وتجربة التأليف المستقلة في `examples/academic-authoring`. هذه العينة المستقلة ليست إعادة تأليف للمحاضرة المحفوظة.

لتحديث تثبيت سابق: احتفظ بمجلد البيانات، واستبدل ملفات البرنامج ثم أعد دخول `nix develop`؛ أو حدّث تبعيات Python بـ`python -m pip install -e .` في بيئتك. إعادة التصدير تكفي لتطبيق التصميم على المحاضرات القائمة، ولا تحتاج تشغيل المؤلف.
